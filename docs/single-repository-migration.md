# 单仓库迁移基础（尚未切换生产）

目标仅保留公开仓库 superke7/global-appliance-intelligence-web（原 GitHub Pages 域名不变）。
现有73个正式 JSON 文件在两个仓库的 blob SHA 一致；无需复制或覆盖新闻历史。
这次仅引入公开批次合同、公开 JSON 校验、当天追加与去重规则、公开事件身份重建和 PR 检验。
不合并原私有仓库的 Git 历史、Issues/PR、运维诊断数据、SSH 配置或 Actions Secrets。

## 公开前审核是硬性要求
公开仓库的任何分支、Pull Request、Issue 或 commit 在正式校验前就可能被外界读取，因此绝不应把现有私有 GAI_PUBLIC_BATCH Issue 的原始提交直接迁入公开仓库。
必须在进入公开 GitHub 前，使用 Google Sheets 的正式 QA 及 ChatGPT 公开数据合同筛选，确保只有已审核的中性公开 JSON 才被提交。
本仓库 validator / CI 是第二道防线，不能逆转一次已经公开的敏感数据提交。

## 安全切换门槛
1. PR 的完整历史批次与事件映射测试成功，站点和 RSS 功能不变。
2. 设计不依赖私有 Issue 的发布前审查及公开仓库写入方法，验证字段、幂等、同时写入处理和失败恢复。
3. 同一次切换中修改07:35/08:05定时任务提示词，确保仅使用新公开仓库；切换前不得更改现有四项任务。
4. 新流程获得合法正式批次的真实成功记录、Pages/RSS 验收成功，连续观察后撤销旧跨仓库 Token 并归档私有仓库。

本 PR 不增加任何生产写入入口，不改变线上部署的定时或新闻内容。
